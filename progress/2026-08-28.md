## Trip taxonomy merge and trip-page fields (branch `feature/content-model-merge`)

Acting on the content model audit from 2026-08-27. Darius answered six decisions up front: keep Combo as a trip type but drop the wizard's "both" answer; remove `difficulty` entirely with rapid class for rafting and "who's this trip for" for biking; do the full scope including Justin's missing fields; shared documents with per-trip override for Packing List / Getting Here / Before You Go; a real `tripType` rename with data migration; and a Studio-facing rename of `river` to Section.

**Schema.** New `tripType` (name, slug, `cardLabel`, `tagColor`, `listsWith`, description, image, order) and `tripInfoSection` (title, slug, body, order). Deleted `activity.ts` and `trip-category.ts`. `trip.ts` rewritten: single required `tripType` ref replaces `activities[]` + `categories[]`, `difficulty` removed, and seven field groups added (Basics, Card, Trip Details, Quick Facts, Booking, Trip Finder, Specialty) over what were 44 flat fields. New fields: `whoIsThisFor`, `meetingPlace`, `deposit`, `whatsIncluded`, `videoUrl`, `infoSections` (ref + `overrideBody`). Every field titled "Description" now names its destination and carries help text. `river.ts` retitled to Section — internal type stays `river` because the route is `/rivers/[slug]` and every reference is keyed to it.

**Studio.** `sanity.config.ts` structure is grouped: Trips, then Pages & Posts and Taxonomy folders, then the pinned singletons, then a Form Submissions folder for the two read-only inboxes. Added singleton template filtering and action filtering, so a second `homepage` can no longer be created (it would have been invisible in the sidebar but still returned by `*[_type=="homepage"][0]`).

**Queries.** The card projection was copy-pasted at eight sites, one of which resolved the ribbon as `coalesce(ribbon, ^.ribbonLabel)` against the others' `specialtyTypes[0]->ribbonLabel` and could disagree for a trip in more than one specialty family. Now a single `TRIP_CARD` fragment interpolated into `defineQuery` — verified typegen resolves it fully, including the `tagColor` union. `riverBySlugQuery` gains `"riverLabel": coalesce(riverName, name)`, closing the mismatch where a card reading "Colorado River" linked to a page headed "Westwater". Dead `allRiversQuery`/`allActivitiesQuery` removed along with the orphaned `homepage.rivers[].tripCount`/`tripSlug` subqueries.

**Components.** `tripCardProps()` added to `TripCard.tsx`, replacing the same 12-line mapping at seven call sites; `TAG_CLASSES` replaces `/bik/i.test(category)`. `ActivityLanding` → `TripTypeLanding`. Trip page: facts bar shows `Class IV` from `maxRapidClass` falling back to `whoIsThisFor`, plus Meet at and Deposit; What's Included checklist; video embed above the gallery; collapsible info-section panels with a "Before You Go" entry in the floating menu. `src/lib/video.ts` normalises YouTube/Vimeo watch URLs to embed URLs (8 tests) — editors paste address-bar links, which would otherwise render a blank iframe.

**Placeholders removed.** "Trip description coming soon. Add it in the Studio." was live on all six production trip pages. Same string existed on the river and blog-post pages; all three now render a shorter page instead.

**Migration** (`scripts/migrate-trip-types.mjs`), deliberately expand/contract. Deployed `main` still reads `activities`/`categories`, so a single-shot migration would have 404'd `/rafting` and `/biking` the moment the activity documents were deleted. `--expand` (applied to production) creates the three trip types, carries the landing-page description and hero image across from the old activity documents, and points all six trips at a type inferred from their old slugs. `--contract` (**not run** — must wait until this branch deploys) unsets `activities`/`categories`/`difficulty` and deletes the four old taxonomy documents; it refuses to run if any trip is unresolved. Idempotent throughout; existing values on the new documents win over legacy ones so re-runs don't clobber Studio edits.

**Verified.** typecheck, eslint, prettier, `pnpm build`, and 125 unit tests (was 117) all pass. Against the local dev server: all six trip cards render the right tag and colour from data, `/rafting` and `/biking` keep their intro copy and hero images (asset ids compared byte-for-byte against production), `/rivers/westwater` shows "Westwater" over "Colorado River", the Westwater facts bar reads Class IV, and the wizard's activity question offers two options plus skip. Production stayed healthy through the expand phase (`/trips/westwater-canyon`, `/rafting`, `/biking`, `/trips` all 200). The Studio sidebar itself was not visually checked — it needs Darius's Sanity login.

**Not done.** The three Trip Info Section documents are unwritten: packing lists for a rafting company are safety-adjacent content in Holiday's voice, not a seed script's. `season`/`seasonMonths`, `duration`/`durationLabel` and `startingPrice`-vs-Arctic remain duplicate encodings — out of scope for this branch. Justin's doc also wants Rates & Dates moved last on the trip page; the section order is untouched since he owns that design. Nothing pushed; branch is local.
