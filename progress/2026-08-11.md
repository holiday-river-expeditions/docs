## Mobile header overflow fix

The header row overflowed on phones and the hamburger rendered on top of the
"HOLIDAY RIVER" wordmark. At 375px (`px-6` → 327px usable) the row demanded
~368px and nothing in it could shrink — the wordmark and the CTA pill are both
`whitespace-nowrap` — so the `justify-end` right cluster overflowed *leftward*
onto the logo. Only reproducible with a non-empty cart, since `MiniCart`
returns `null` at count 0.

- `Button.tsx`: new `compact` size — `px-4 py-1.5 text-[16px]`, stepping up to
  `default`'s metrics at `md:`. The responsive step lives inside `sizeStyles`
  rather than a passed `className`, because Tailwind resolves same-specificity
  conflicts by stylesheet order, not attribute order (`px-6` would have beaten
  a passed `px-4`).
- `Header.tsx`: logo `text-[26px] sm:text-[32px] md:text-[48px]`; right cluster
  `gap-1.5 sm:gap-2 md:gap-3`; row padding `px-4 sm:px-6 md:px-12` + `gap-2`;
  CTA `size='compact'`. `shrink-0` on both the logo link and the right cluster.
- New `e2e/header.spec.ts` (3 tests at a 375×812 viewport, cart cookie seeded).

Measured at 375px: 42px clearance between wordmark and hamburger, CTA 16px off
the right edge, no overflow. Desktop is byte-identical (19px/24px CTA, logo
centered at offset 0 at both 1024 and 1280).

### Decisions

- **All four elements stay visible on mobile** — scale everything down rather
  than hiding the wordmark or moving BOOK NOW into the drawer. Per
  [[ui-patterns]] the header CTA is a primary conversion surface.
- **375px is the supported floor.** At 320px the row still needs ~345px, so it
  degrades — but only to a hairline overflow, not a collision.
- **`shrink-0` on the logo link, not `min-w-0`.** `min-w-0` looked right but
  made things worse: the lockup's mark is an auto-width `next/image` that
  contributes 0 to min-content, so the link compressed while the nowrap
  wordmark spilled out beyond its own box — reproducing the original overlap in
  a form the link's bounding box could not detect. The e2e test measures the
  wordmark span for the same reason.

### Noticed, not fixed

- `MobileNav` and `MiniCart` each own independent open state with no
  coordination, and both use `z-50` — the drawer and cart popover can overlap.
- `Logo.tsx` declares `width={119} height={200}` while `public/logo-icon-red.svg`
  is 1189×2002. Same aspect ratio, so rendering is unaffected.

## Session 2 — "A Day on the River" video panel

The itinerary section read as flat: a dark evergreen band with a `max-w-3xl`
accordion and a large empty right side, in the one section whose job is to
convey what a day actually feels like. Added a per-trip ambient video panel.

### Shipped

- **Schema** — `trip.itineraryMedia` object (`video` file / `poster` image,
  required / `alt`, required), collapsible in the Studio. `pnpm typegen` run;
  `schema.json` + `src/sanity/types.ts` regenerated.
- **GROQ** — `itineraryMedia` projected in `tripBySlugQuery` with
  `video.asset->url` dereferenced; poster stays raw and goes through the
  existing `imageUrl()` builder.
- **`AmbientVideo`** (new client component) — silent looping panel with a
  deliberate no-`autoPlay` contract.
- **`ItinerarySection`** — split layout: sticky media panel left, accordion
  right, stacked on mobile. Three-way fallback: video → poster still →
  original single-column band, unchanged.
- **Tests** — 5 colocated Vitest cases (fallback branches + the no-autoplay
  contract); `e2e/itinerary-video.spec.ts` covering reduced-motion and the
  pause control, self-skipping until a clip is uploaded.

### Decisions

- **Sanity file assets, not Mux/Cloudflare Stream.** Overkill for a silent
  ~10s loop, and no new vendor. Revisit if video spreads to the hero —
  Sanity has no adaptive bitrate. Watch CDN bandwidth after launch.
- **MP4/H.264 only, no WebM.** A second file field doubles the upload burden
  on editors for ~30% size; H.264 plays everywhere including iOS.
- **The poster gates the panel.** It's the video's poster frame, the
  reduced-motion still, and the no-video fallback all at once, so a trip with
  no poster gets no panel regardless of what else is set.
- **No `poster` attribute on `<video>`.** The still renders underneath as a
  `next/image`, which gets webp negotiation and the editor's hotspot crop;
  the attribute would double-fetch the same frame.
- **Motion is a JS decision, not a CSS one.** `autoPlay` is a static JSX
  attribute that `prefers-reduced-motion` cannot revoke, so the server never
  emits it. With `preload='none'`, a reduced-motion or no-JS visitor fetches
  **zero video bytes** — not just zero motion.
- **Pause control is required.** WCAG 2.2.2 covers auto-starting motion past
  5s; axe does not check it, so it needs manual verification. The control
  renders only once playback has actually begun.

### Notes

- `AmbientVideo` carries the same **dead-observer failsafe** as
  `RevealObserver` — found the hard way: the preview browser supports
  IntersectionObserver but never delivers callbacks, so the loop silently
  never started. Falls back to a one-shot geometry check after 3s.
- `src/vitest-setup.ts` gained RTL `cleanup` (auto-cleanup only self-registers
  with Vitest globals, which this project doesn't enable — a second `render()`
  in one file was finding duplicates) and a `matchMedia` stub (absent in jsdom).

## Session 3 — Typography audit: Dates & Availability

Started as a review question ("does the booking section have good typography?").
The hierarchy turned out to be sound — month subhead → date row → seats badge →
CTA reads cleanly, and the smaller teal 15px eyebrow above 28px date rows is the
right inversion (color and tracking carry that level, not size). Three defects
underneath it, each a contradiction of a convention the codebase already sets.

### Shipped

- **Badge leading unified.** The `px-3.5 py-1.5 text-[14px] font-bold` badge
  appears 10× site-wide; 8 used `leading-tight`, 2 used `leading-none`
  (`AvailabilitySection`, `open-seats`). `leading-none` is the worse value — a
  1.0 line box at 14px puts the descender in "Next available: **Sep**" against
  the padding edge. Now 10/10 `leading-tight`, confirmed in the DOM (17.5px).
- **`Button.tsx` is now the single source for button typography.** Six call
  sites hand-rolled its class string and had drifted to `tracking-wide`, which
  no variant had — three tracking values across visually identical buttons.
  Exported `buttonClasses()` so the elements `<Button>` can't render
  (`ExternalLink`, `tel:` anchor, `<summary>`, disabled submit) share one
  definition. Migrated `DepartureList` ×3, `BookingRow` ×2, `MiniCart`,
  `book/page`. Added `sm` and `xl` sizes.
- **`--text-section` (36px/0.9).** The site's most-used section heading had no
  token — the scale jumped h3 28px → h2 44px, skipping the size actually used
  most. Replaced 14 hand-written `text-[36px] leading-[0.9]` pairs.

### Decisions

- **Adopted `tracking-[0.025em]` on `default`** rather than stripping
  `tracking-wide` off the booking CTAs. Uppercase condensed gothic wants a
  little tracking, and it made the migration a zero-visual-diff change on the
  highest-stakes surface. Verified: booking CTAs still compute 0.475px; the
  cost is ~4px of width on `default` buttons elsewhere (Book Now 114.8→118.6),
  `lg` untouched.
- **`sm` size instead of forcing `default` into MiniCart.** Measured the
  checkout label against the 240px panel: 215px at 19px on the brand face but
  **256px on the Oswald fallback — an overflow**. The original 17px was load-
  bearing, not arbitrary. Consistency of *system*, not of one size.
- **`Logo.tsx` keeps arbitrary sizes.** Bare font-size utilities emit no line
  height; the lockup sets its own leading to match the mark, so `text-section`
  would impose 0.9 on it.
- **`blog/page.tsx` keeps an explicit `leading-[0.9]`** beside
  `text-section … md:text-h2`: it sets `--tw-leading`, which `md:text-h2`
  defers to via `line-height: var(--tw-leading, .95)`. Dropping it would hand
  the md breakpoint to h2's 0.95.

### Verified

Typecheck, lint, 37 unit tests green. Computed styles before/after prove the
token swap is a no-op (36px/32.4px identically); h2 fits one line at 375px
(313.8px) with no horizontal scroll; `/open-seats` all 12 groups' badges at
17.5px. Screenshots come back blank in this preview pane — verification is by
computed style and geometry, which is stronger evidence for typography anyway.

**Not exercised:** the `Book` ExternalLink path. Arctic returns no
`onlinebookingurl` in this environment, so every row renders "Call to Book".
Checked by construction instead — the composed class string carries exactly one
display utility. Likewise `BookingRow`'s buttons: `BOOKING_NATIVE` is empty in
`.env.local`, so the native flow never mounts.

### Also fixed — the `leading-*` classes were dead

Found while documenting the token swap: `leading-h1`, `leading-h2`, `leading-h3`,
`leading-subheading`, `leading-paragraph`, `leading-body` and `leading-link`
compiled to **zero CSS rules**. Tailwind resolves `leading-*` from a
`--leading-*` namespace and the theme had only ever defined the
`--text-*--line-height` pairs, which feed the font-size utilities alone. ~78 uses
across `src/`, all inert.

It hid because every single use sits beside its matching `text-*` sibling, which
applies the same value anyway — the site rendered correctly for the wrong
reason. The live cost was that an *override* silently did nothing.

Fixed by defining the eight `--leading-*` tokens in `globals.css`. Chose this
over deleting the 78 classes: it makes the documented API real instead of
removing it, and it's a much smaller diff.

- **Values are duplicated by hand on purpose.** They can't reference the
  `--text-*--line-height` pairs via `var()` — `@theme inline` inlines values
  rather than emitting `:root` custom properties, so a `var()` there resolves to
  empty. Same trap the body font already documents. Commented in both places.
- **Proven a no-op before shipping.** Audited all 63 class strings containing a
  `leading-*` token: every one pairs with a `text-*` of the same token at the
  same breakpoint, so nothing could shift. Re-measured after: h2 36/32.4,
  badges 14/17.5, date cells 28/28, hero 64/58.88 — all identical.
- **Overrides now work**, confirmed live: `text-body leading-h1` → 14.72px,
  `text-h1 leading-body` → 22.4px, `text-paragraph leading-h3` → 18px. Every one
  of those was previously ignored.

### Noticed, not fixed

- Other off-scale sizes remain (`text-[14px]`, `[15px]`, `[13px]`, `[11px]`…) —
  a separate question about whether the scale needs a small-text tier.
