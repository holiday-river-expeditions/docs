## Mobile header overflow fix

The header row overflowed on phones and the hamburger rendered on top of the
"HOLIDAY RIVER" wordmark. At 375px (`px-6` → 327px usable) the row demanded
~368px and nothing in it could shrink — the wordmark and the CTA pill are both
`whitespace-nowrap` — so the `justify-end` right cluster overflowed *leftward*
onto the logo. Only reproducible with a non-empty cart, since `MiniCart`
returns `null` at count 0.

- `Button.tsx`: new `compact` size — `px-4 py-1.5 text-[16px]`, stepping up to
  `default`'s metrics at `md:`. The responsive step lives inside `sizeStyles`
  rather than a passed `className`, because Tailwind resolves same-specificity
  conflicts by stylesheet order, not attribute order (`px-6` would have beaten
  a passed `px-4`).
- `Header.tsx`: logo `text-[26px] sm:text-[32px] md:text-[48px]`; right cluster
  `gap-1.5 sm:gap-2 md:gap-3`; row padding `px-4 sm:px-6 md:px-12` + `gap-2`;
  CTA `size='compact'`. `shrink-0` on both the logo link and the right cluster.
- New `e2e/header.spec.ts` (3 tests at a 375×812 viewport, cart cookie seeded).

Measured at 375px: 42px clearance between wordmark and hamburger, CTA 16px off
the right edge, no overflow. Desktop is byte-identical (19px/24px CTA, logo
centered at offset 0 at both 1024 and 1280).

### Decisions

- **All four elements stay visible on mobile** — scale everything down rather
  than hiding the wordmark or moving BOOK NOW into the drawer. Per
  [[ui-patterns]] the header CTA is a primary conversion surface.
- **375px is the supported floor.** At 320px the row still needs ~345px, so it
  degrades — but only to a hairline overflow, not a collision.
- **`shrink-0` on the logo link, not `min-w-0`.** `min-w-0` looked right but
  made things worse: the lockup's mark is an auto-width `next/image` that
  contributes 0 to min-content, so the link compressed while the nowrap
  wordmark spilled out beyond its own box — reproducing the original overlap in
  a form the link's bounding box could not detect. The e2e test measures the
  wordmark span for the same reason.

### Noticed, not fixed

- `MobileNav` and `MiniCart` each own independent open state with no
  coordination, and both use `z-50` — the drawer and cart popover can overlap.
- `Logo.tsx` declares `width={119} height={200}` while `public/logo-icon-red.svg`
  is 1189×2002. Same aspect ratio, so rendering is unaffected.

## Session 2 — "A Day on the River" video panel

The itinerary section read as flat: a dark evergreen band with a `max-w-3xl`
accordion and a large empty right side, in the one section whose job is to
convey what a day actually feels like. Added a per-trip ambient video panel.

### Shipped

- **Schema** — `trip.itineraryMedia` object (`video` file / `poster` image,
  required / `alt`, required), collapsible in the Studio. `pnpm typegen` run;
  `schema.json` + `src/sanity/types.ts` regenerated.
- **GROQ** — `itineraryMedia` projected in `tripBySlugQuery` with
  `video.asset->url` dereferenced; poster stays raw and goes through the
  existing `imageUrl()` builder.
- **`AmbientVideo`** (new client component) — silent looping panel with a
  deliberate no-`autoPlay` contract.
- **`ItinerarySection`** — split layout: sticky media panel left, accordion
  right, stacked on mobile. Three-way fallback: video → poster still →
  original single-column band, unchanged.
- **Tests** — 5 colocated Vitest cases (fallback branches + the no-autoplay
  contract); `e2e/itinerary-video.spec.ts` covering reduced-motion and the
  pause control, self-skipping until a clip is uploaded.

### Decisions

- **Sanity file assets, not Mux/Cloudflare Stream.** Overkill for a silent
  ~10s loop, and no new vendor. Revisit if video spreads to the hero —
  Sanity has no adaptive bitrate. Watch CDN bandwidth after launch.
- **MP4/H.264 only, no WebM.** A second file field doubles the upload burden
  on editors for ~30% size; H.264 plays everywhere including iOS.
- **The poster gates the panel.** It's the video's poster frame, the
  reduced-motion still, and the no-video fallback all at once, so a trip with
  no poster gets no panel regardless of what else is set.
- **No `poster` attribute on `<video>`.** The still renders underneath as a
  `next/image`, which gets webp negotiation and the editor's hotspot crop;
  the attribute would double-fetch the same frame.
- **Motion is a JS decision, not a CSS one.** `autoPlay` is a static JSX
  attribute that `prefers-reduced-motion` cannot revoke, so the server never
  emits it. With `preload='none'`, a reduced-motion or no-JS visitor fetches
  **zero video bytes** — not just zero motion.
- **Pause control is required.** WCAG 2.2.2 covers auto-starting motion past
  5s; axe does not check it, so it needs manual verification. The control
  renders only once playback has actually begun.

### Notes

- `AmbientVideo` carries the same **dead-observer failsafe** as
  `RevealObserver` — found the hard way: the preview browser supports
  IntersectionObserver but never delivers callbacks, so the loop silently
  never started. Falls back to a one-shot geometry check after 3s.
- `src/vitest-setup.ts` gained RTL `cleanup` (auto-cleanup only self-registers
  with Vitest globals, which this project doesn't enable — a second `render()`
  in one file was finding duplicates) and a `matchMedia` stub (absent in jsdom).
