## Per-browser demo flags system + logo revert

Built the demo-flags admin overlay Darius requested: a way to toggle demo ideas on production per-browser, with the bold logo as the first flag. Decisions made with Darius during planning: per-browser scope (localStorage, no Sanity, real visitors always get defaults), floating overlay armed via `/admin`, and first flag = classic SVG lockup vs bold live-text lockup.

Implementation:

- `src/lib/demo-flags.ts` — flag registry (single source of truth: id/label/description per flag), `hre_demo` storage key, zod-parsed state with disarmed fallback for malformed storage (same convention as `cart-cookie.ts`), and `DEMO_INIT_SCRIPT`, a blocking inline script generated from the registry that stamps `data-demo-<id>='on'` on `<html>` before first paint (no flash, no hydration mismatch; `suppressHydrationWarning` added to `<html>`).
- `Logo.tsx` now renders both treatments server-side; Tailwind v4 arbitrary variants (`[[data-demo-logo-bold=on]_&]:hidden` / `:inline-flex`) pick one, so Header/Footer stay static and ISR-cacheable. **Default is now the original horizontal SVG lockup (`/logo-horizontal-red.svg`) — this also lands the Aug 20 "go back to the original logo" decision, which had not been implemented in code.** The bold stacked live-text lockup from the Aug 11 design batch is behind the flag. Hidden variant is `display:none`, so no duplicate accessible names; the SVG keeps `alt=''` because both call sites wrap the lockup in an `aria-label`ed link.
- `DemoFlagsPanel.tsx` — client overlay modeled on MiniCart (`useSyncExternalStore` over the raw localStorage string, invalidated by `hre:demo-updated` + native `storage` events). Renders nothing unarmed; armed browsers get a collapsed "Demo" pill bottom-right that expands to per-flag checkboxes, Reset all, and Disarm. Toggles flip the `<html>` attribute live, no reload. Ctrl+Shift+D toggles expansion.
- `/admin` (server page, `robots: noindex`, added to `RESERVED_SLUGS`) mounts `ArmDemo`, which merges `armed: true` into existing state and `router.replace('/')`. Unauthenticated by design — flags only affect the visitor's own browser.
- Tests: `demo-flags.test.ts` (parse fallbacks, init-script behavior evaluated in jsdom), `DemoFlagsPanel.test.tsx` (armed/unarmed render, toggle writes storage + attribute, reset/disarm), new `e2e/demo-flags.spec.ts` (default visitor, arm, live flip, reload persistence at domcontentloaded, reset, disarm). `e2e/header.spec.ts` wordmark locator repointed at the visible classic image since `span span` would now also match the hidden bold lockup.

Verification: typecheck, lint, 62 unit tests, 13 e2e tests (incl. axe a11y suite), and production build all pass. Browser-verified the full arm → toggle → reload → disarm loop against the dev server; note the post-`/admin` redirect restores scroll position, which looked like a blank page during verification but is standard scroll restoration, not a bug.

During planning, a mockup of the overlay was rendered as an interactive widget in-chat (faux browser + real logo SVGs) before Darius approved the plan.

Docs synced: `architecture.md` — `/admin` route, logo-default note under Navigation, new "Per-Browser Demo Flags" section. Caveat recorded there: `/arctic-template` carries its own hardcoded logo and does not participate in demo flags.

Flagged to Darius (his files, not edited): `open-decisions.md` has no entry for the Aug 20 logo decision or the demo-flags approach; the Aug 20 revert is now implemented as the site default.
