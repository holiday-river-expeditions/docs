### Dependency vulnerability cleanup

Triaged and cleared the 62 Dependabot alerts (1 critical, 27 high, 26 moderate, 8 low) that accumulated on the website repo since the last clean sweep on 2026-05-28. `pnpm audit` now reports **no known vulnerabilities**.

Same strategy as the May pass: patch in place within semver ranges, plus targeted `pnpm.overrides` for the stragglers. The one deliberate exception is the `next` minor bump, explained below.

**Direct bumps**

- **`next` 16.2.6 → 16.3.0** (`eslint-config-next` in lockstep) — cleared 14 alerts on its own: DoS in Server Actions, SSRF in Server Actions on custom servers, SSRF in rewrites, Turbopack middleware/proxy bypass, Image Optimization SVG DoS, two cache-confusion advisories, and internal Server Function endpoint disclosure.
  - The advisories only required ≥ 16.2.11, and 16.2.12 was applied first. Went the extra step to the 16.3.0 **minor** because it is the *supported* fix for the `sharp` alert — 16.3.0 declares `sharp: ^0.35.3`, whereas 16.2.x pins `^0.34.5`. This avoids force-overriding `sharp` past the range Next declares for it.

**Refreshed within existing ranges**

`pnpm update` did the bulk of the work — the Sanity toolchain moved (`sanity` 5.27.0 → 5.31.1, `@sanity/client` 7.22.0 → 7.26.2) and pulled patched transitives with it. This alone resolved ~40 alerts:

## Decisions

- **`next` 16.2 → 16.3 minor was worth it.** Taking the minor is lower risk than force-overriding `sharp` to 0.35 against Next's declared `^0.34.5`, since `sharp` is genuinely in the production image-optimization path. Gated by the full check suite plus a browser smoke test.
- **Forced `adm-zip` to 0.6.0 across `@sanity/runtime-cli`'s declared `^0.5.17`.** No fix exists in the 0.5.x line (0.5.18 is the latest and is still vulnerable). Verified before forcing: the public API surface is *identical* between 0.5.18 and 0.6.0, and `@sanity/runtime-cli` only calls `addLocalFile`, `addLocalFolder` and `toBuffer` — all write-path methods, whereas the advisory is in the decompression path. Exposure was negligible either way (it zips Sanity Function bundles from local files; it never opens untrusted archives).
  - The clean fix is `@sanity/runtime-cli` 17.x, which declares `adm-zip: ^0.6.0` — but that only arrives via the **sanity 5 → 6 major**. Worth smoke-testing `sanity functions` commands before relying on them.
- **Held all majors**, consistent with the May decision. No application code changes.
