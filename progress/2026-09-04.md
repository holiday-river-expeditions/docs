## Trip finder: questions moved into Sanity, logic panel, docs (branch `feature/trip-finder-sanity-spec`)

Started from Darius's two questions (is the wizard a Sanity-driven spec Holiday can edit; Sanity or Arctic) and his decision that it should be driven completely by Sanity. Scope agreed: words, pictures, and dials move to Sanity; the five scoring formulas stay in code; the logic panel from the demo is built second.

**Schema.** New `tripFinderSpec` singleton (`src/sanity/schemas/trip-finder-spec.ts`) with object types `tripFinderQuestion`, `tripFinderOption`, `tripFinderCondition`. Question: `kind` (one of six, unique across the document, doubles as the URL param), copy fields, hotspot image with required alt, `weight` 1–5 (hidden for `who`), `onlyWhen`/`skipWhen` conditions, `options[]`. Option: `value` (regex `^[a-z0-9-]+$`, `skip` reserved, unique within a question), label/sublabel/bikeSublabel, and five dial fields (`targetClass`, `floorAge`, `centerDays`, `month`, `tripType` ref) of which one is shown and required per the owning question's kind. Sanity's `hidden`/`validation` callbacks only see the immediate parent, so `kindOfOption()` walks `document.questions` for the question whose options contain the option's `_key`. Typing the shared `dial()` helper against `NumberRule | ReferenceRule` needed a generic with an `as unknown as R` cast. Added to `singletonTypes` in `sanity.config.ts` and pinned under Site Settings. `MONTHS` exported from `trip.ts` for reuse. `pnpm typegen` regenerated `TripFinderSpecQueryResult`.

**Boundary.** `src/lib/trip-finder-spec.ts`: Zod schema over the query result (loose object for the image so hotspot/crop survive), `normalizeTripFinderSpec()` (pure, returns `{spec}` or `{error}`), `resolveTripFinderSpec()` (fetch + normalize, warns and returns `DEFAULT_TRIP_FINDER_SPEC` on any failure, never throws). `spec.source` is `'sanity' | 'fallback'`.

**Refactor.** `src/lib/trip-finder.ts` rewritten around a `TripFinderSpec` argument. `TRIP_FINDER_QUESTIONS` → `DEFAULT_TRIP_FINDER_SPEC` with dials, weights and conditions folded in; answers are now `Record<QuestionKind, string | null>` (option value or `'skip'`); scorers take dials, not option values; `isApplicable` evaluates `onlyWhen`/`skipWhen` generically; follow-ups share their parent's progress slot; `answersToParams` drops follow-ups when the parent drops; `scoreTrips` scores only applicable questions (a leftover thrill answer after switching to bike no longer counts) and emits a per-question `breakdown` on every `TripMatch`; formula constants exported as `SCORING`; `MIN_CONFIDENT_SCORE` and the results count moved into `spec.tuning`. `parseTripFinderParams` accepts only values the spec offers, so a `month=1` link no longer parses to a number. Components take `spec` as a prop; `RiverProgress` now places N markers along the cubic path (`pointOnRiver`) instead of a 4/5 lookup. Both `/trip-finder` and the homepage fetch the spec in their `Promise.all`.

**Seed.** `scripts/seed-trip-finder-spec.mjs` imports the default spec from the `.ts` module under `node --experimental-strip-types` (Node 22.15) rather than duplicating 180 lines of copy. Uploads the six wizard backgrounds (skipping assets already present by `originalFilename`), resolves activity dials to `trip-type-*` ids, `createOrReplace` on `_id: 'tripFinderSpec'`. Dry run by default, `--write` to apply. Darius ran the write against production; verified in the browser that the wizard renders the Sanity copy and CDN photos with no fallback warning, and that the age follow-up rule fires from the document.

**Logic panel.** `finder-logic` demo flag. `TripFinderLogicPanel` (server component, native `<details>`, CSS-gated) mounted under both the wizard and results in `page.tsx`; the wizard branch now fetches the catalog too so the running ranking shows on every step. Sections: source + Studio link, answers table with dial/weight/rule, full ranking with per-question breakdown (asked-for vs trip fact vs score × weight vs reason), data sources (Sanity facts, Arctic join and status, availability), missing-facts worklist, settings in use. The axe scan caught `text-onyx/60` (3.91:1) and `/50`; onyx is `#2c2b29`, so `/70` is the floor on white and `/85` on sand. Existing e2e `getByText('Best Match')` became ambiguous against the panel's "Best Match threshold" text; made exact.

**Tests.** 144 unit (was 125): threaded suite, new spec-driven-rules block with a custom spec, breakdown sums, spec boundary rejections (duplicate kinds, missing dial, unsafe/reserved values, no photo), panel render. 25 e2e green including the new flag-on/flag-off panel test and an armed axe scan of the panel.

**Docs.** New `reference/trip-finder.md` (plain-English: what is editable, what needs a developer, how a pick is made, Sanity vs Arctic, the panel, known gaps, technical notes) and `reference/demo-panel-guide.md` (turning on `/admin`, every switch as of today, caveats). Editor guide gains a Trip Finder cheat-sheet row and subsection; `sanity.md` and `architecture.md` updated for the new types, the flag roster, and links.

**Not done.** Nothing committed or deployed yet at time of writing. `open-decisions.md` still lists the trip finder as `#decision-needed` (Darius's file, flagged not edited).
