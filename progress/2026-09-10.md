- **Two bugs found in the browser, both real.** (1) MapLibre rejects `['*', boost, ['interpolate', …, ['zoom'], …]]` — `zoom` must be the top-level interpolate, so the per-feature boost now multiplies each stop's output instead. (2) MapLibre 6 resolves its worker as `new URL('./maplibre-gl-worker.mjs', import.meta.url)`, which under Turbopack points at a chunk URL with no sibling file: the worker 404s (the six recurring 404s + "non-JavaScript MIME type" console errors), and every GeoJSON source stays unloaded forever — `isSourceLoaded` false, zero features — while raster tiles render fine, which is why the homepage map never showed the problem. Fix: `scripts/copy-maplibre-worker.mjs` copies `maplibre-gl-worker.mjs` + `maplibre-gl-shared.mjs` into gitignored `public/maplibre/` on `postinstall`, `dev` and `build`; `src/lib/maplibre-worker.ts` calls `setWorkerUrl('/maplibre/maplibre-gl-worker.mjs')` at module scope in both map components. `public/maplibre/**` and `src/lib/river-stretches.json` are excluded from ESLint/Prettier (Prettier had expanded the JSON to 205 KB / 5,545 lines).
- Debugging note: react-map-gl exposes no global map handle; walking React fibers from `.maplibregl-map` to the `useState` holding `{map}` and calling `querySourceFeatures`/`isSourceLoaded` was what surfaced the worker failure. Also, the in-app browser pane doesn't paint WebGL while hidden, so map screenshots need the tab fronted.
